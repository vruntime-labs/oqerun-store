## Memory rules
At the start of a session, read this file and the current repository state. Treat memory as historical context, not a replacement for source inspection. If notes conflict, surface the conflict rather than silently choosing.

Record durable decisions, fixes, discoveries, tests, and blockers. Each observation should have an ID, date, project, type, title, summary, reason, affected files, verification status, and evidence. Separate requested changes from implemented changes. Never invent dates, tests, commits, or file paths. Never store credentials, tokens, passwords, private keys, or sensitive personal information.

When the user asks to wrap up or save the session, update this file with a concise summary, completed work, unresolved work, and next step. Do not claim automatic capture or background monitoring.
