# ChatGPT Taste Skill — Oqerun Store adaptation

## Purpose
Create interfaces with a clear product identity, strong visual judgment, and a deliberate relationship between content, layout, and interaction. Avoid generic AI-generated store templates.

## Classify before designing
Identify the work as one of:
1. Public-facing page (store landing, catalog, app detail, submission page).
2. Application screen (search, filters, install dialog, publisher details, settings).
3. Existing-project redesign or refinement.

Inspect the actual brief, source files, assets, and existing UI before deciding. Do not design from assumptions when source evidence is available.

## Establish the direction
Define:
- Primary audience and the task they need to complete.
- The most important information for that task.
- Oqerun Store's relationship to Oqerun OS.
- A distinct visual concept appropriate to an open-source software catalogue.
- The real content and assets available, including verified app names, icons, screenshots, publisher details, licenses, and permissions.

For existing work, identify the three highest-impact issues and preserve working components. Do not replace a functioning interface just to make it look different.

## Store-specific taste principles
- Make discovery and trust equally clear: users should understand what an app does and who publishes it before installing.
- Give search, categories, filters, app cards, app detail, and install states clear hierarchy.
- Use real catalog data. Never invent ratings, reviews, downloads, endorsements, publishers, screenshots, or compatibility claims.
- Distinguish publisher-submitted metadata from independently verified information.
- Make app source, license, version, permissions, and launch/install behavior easy to inspect.
- Empty, loading, error, unavailable, and unverified states should be designed intentionally.
- Keep desktop and mobile layouts equally usable.

## Quality bar
A design should feel intentional, recognizable, readable, calm, and coherent. Every visual choice should support navigation, discovery, comprehension, or trust. Avoid generic template layouts, random decoration, excessive glass effects, and superficial polish that hides weak information architecture.

## User's explicit brand constraints
Never use purple gradients, pill-shaped buttons, fake reviews, fake metrics, vague hero text, emoji icons, em dashes, over-the-top scroll animations, AI-slop photos, AI-slop copy, cursor animations, or fake customer counters. Do not add a Made with AI tag. No custom domain is required for the current GitHub Pages hosting plan.
